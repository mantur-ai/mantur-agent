# Agent Note: 从已确认版本重连编辑器保存

Status: implemented

[English](2026-10-24-mantur-cut-persisted-save-base.md) | 中文

## 问题

编辑器含未保存修改时，内存文档版本不同于已保存文档。Bridge 断连后用该内存版本注册，会使服务器拒绝注册并返回 stale，即使没有其他编辑器修改工程。清空本地文档或采用服务端最新版本可能丢失或覆盖工作。这个条件性缺陷不能证明所有已观察到的保存或导入失败都由它引起。

## 决策

维护的[编辑器关闭补丁](../../../../packages/client/ui-mantur-editing/adapters/mantur-cut-shutdown.patch)将已确认的持久化版本与当前编辑文档分开。接受已加载工程时建立持久化版本；被接受的保存回执推进该版本。清理连接占用会保留该版本及未保存文档。编辑上下文身份和注册 capability 阻止失效的加载、注册、回执和清理影响替代上下文。注册使用已确认版本，编辑工具校验继续使用当前文档版本。

服务器持有工程存储锁时，将预期版本与已保存文档比较。占用身份和 epoch 校验仍为必要条件。另一浏览器不能接管活跃浏览器租约；释放或到期后，新申请仍必须匹配调用方已知的持久化版本。stale 响应不授权采用服务端版本并覆盖其文档。保存失败继续阻止离开编辑器。

[桌面源码配置](../../../../apps/desktop/mantur-cut/source.json)固定补丁及结果树。无需修改 harness 核心包。[关闭决策](2026-09-08-mantur-editing-owned-shutdown.zh.md)和[工具结果版本决策](2026-09-09-mantur-editor-result-revision.zh.md)仍分别保证排空与完成语义。

## 考虑过的替代方案

**注册当前内存版本。** 未保存编辑不能证明服务端持久化文档的状态，因此会拒绝本可恢复的断连。

**获取服务端最新版本并重试未保存文档。** 这会把另一编辑器的写入当作覆盖授权。

**移除版本或占用校验。** 磁盘写入串行化本身不能证明调用方编辑的是将被替换的文档。允许活跃浏览器接管还会使竞争编辑器反复令对方失效。

## 影响

持久化基线仍匹配时，重连可以保留未保存工作。冲突保留本地草稿并要求明确恢复，不会自动合并。缺少回执的结果仍不确定，完整页面重载不会重建内存草稿。

验证要求使用真实 loopback HTTP 路由和隔离文件存储，覆盖未保存状态下重连、保存及重开，已确认基线推进，陈旧保存和 owner 竞争。源码验证不能代替打包桌面验收，也不能在缺少请求和响应证据时诊断历史故障。新候选打包及已安装客户端保存重开检查仍为独立发版要求。

仓库要求的录制会话场景仍待完成；所属模块的 HTTP 断言不能替代它。
