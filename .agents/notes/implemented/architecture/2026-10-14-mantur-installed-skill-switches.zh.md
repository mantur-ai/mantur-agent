# Agent Note: 已安装技能开关与中文指令菜单

Status: implemented

[English](2026-10-14-mantur-installed-skill-switches.md) | 中文

## Problem

已安装技能没有可见的管理入口，用户无法关闭技能引用；指令英文名称与技能混在一个菜单中。

## Decision

漫途技能广场提供本地已安装技能管理，并在当前 Harness home 持久化关闭的技能名称。更新保留开关状态，因为用户偏好不由版本文件拥有。开关适用于所有同名版本与提供者。历史指令消息保持不变；此功能控制技能调用，不控制文件系统访问。

原技能注册表具有提供者定义的调用标志，但没有部署策略扩展点。`packages/skill/skill/src/index.ts` 与 `src/types.ts` 增加 `skills/enabled`：拒绝时目录中的两个调用标志为 false，正文读取在提供者加载前后检查策略。漫途插件提供持久化策略，并检查精确内置引用路径，避免只隐藏界面条目却仍能直接加载。移除策略监听器后恢复普通注册表行为。

`packages/client/ui-commands/src/client/service.ts` 对已知指令的标签进行本地化，同时保留标准候选值用于执行和英文搜索。输入触发菜单维持指令在上、技能在下的顺序，显示分隔线，并扩大受可用空间约束的视口。现有扩展点无法单独为漫途定义这些核心显示标签。

## Alternatives considered

只隐藏菜单条目不能阻止手动调用。删除技能目录会丢失用户文件，也不适用于只读应用资源。

## Consequences

关闭对后续技能加载生效，保留历史对话与本地文件。管理页展示当前客户端本地目录和内置清单；不枚举其他项目专属技能。

## Verification

升级验证覆盖 Host 重建后的状态保留、注册表正文读取拒绝、加载过程中的关闭、精确内置引用拒绝、保存开关失败、中文菜单选择与标准指令执行。本地验收应用使用同一配置及生成的 Remote 方法。

Mantur 配置启用名为 `mantur-global-skills` 的 Host 文件系统提供方，让管理页在会话预设尚未挂载时也能发现用户已安装技能。预设提供方继续负责各自作用域的发现。

输入框的指令按钮在指令下方包含技能组。`toggleSource` 接受显式指定的额外分组，保留注册顺序及原有引用选择行为。这里修改 `ui-conversation` 的按钮接线，是因为原先的单来源调用排除了已安装技能；入口回归验证从组合菜单中选择技能。
