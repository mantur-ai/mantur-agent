# Agent Note: 桌面更新的显式安全停止

Status: proposed

[English](2026-09-07-desktop-safe-update-stop.md) | 中文

## Problem

安装器需要证明本地执行已经停止，且最终记录已持久保存。Cordis 销毁会收敛清理异常，普通 agent 取消会清空待处理输入，持久化 writer 也可能在关闭失败后退出活动注册表。这些完成信号都不能单独授权安装。异步提示词组装前已领取的输入还需要明确的执行阶段记录，以区分可恢复输入与可能已经执行的工作。

## Proposal

桌面更新模块先取得现有的持久草稿修订号。Host 协调器随后同步冻结工作准入，覆盖工厂启动及已有 agent，在保留未执行输入标识的前提下停止本地执行，并等待工具结果、维护操作、后台进程及 PTY。它必须保留每个参与 writer 的失败结果，遇到不支持的事件生产者时拒绝更新，不能推测其已经静止。远端付费任务不被取消。

所有事件生产者停止后，协调器取得最终会话记录及持久 flush 结果，禁止后续追加，并返回绑定本次更新请求的证据。安装必须同时取得此回执与草稿修订号。子进程退出和通用销毁均不能替代回执；最终检查点之后不再运行会产生事件的清理。

本地 subprocess provider 提供显式停止操作，关闭 spawn 准入、等待所拥有的进程树和终端、保留失败目标，并为重复调用保留失败结果。此操作单独不能证明会话持久化或完整 Host 关闭。其余准入和持久化修改只在插件钩子无法强制执行时进入现有所有者；每个受影响的上游文件都需要有针对性的升级回归测试。

[草稿检查点决策](../../implemented/architecture/2026-09-06-desktop-draft-checkpoints.zh.md)仍负责草稿存储。[Host 退出清理决策](../../implemented/bug-fix/2026-08-11-synchronous-subprocess-exit-cleanup.zh.md)继续负责普通进程退出。这两项决策均未被完全取代。

## Alternatives considered

只停止已注册 agent 会遗漏未发布的 setup 和脱离前台的 job。先销毁再 flush 可能隐藏失败 writer 并清空队列。重试结果不明的输入可能重复执行或扣费。为此次桌面操作另造通用任务运行时并无必要。

## Acceptance criteria

- 确定性 barrier 覆盖启动、inbox 领取、维护、工具收尾、完整进程树退出、writer 关闭失败及迟到追加；每种不安全结果都拒绝安装。
- 重复及过期更新请求不能重复安装，也不能释放另一请求的锁。
- 新的隔离进程重新加载所承诺的精确事件范围、待处理消息 ID、草稿修订号和原始图片摘要。
- Windows x64、Mac arm64 和 Mac x64 分别提供最终修订版的原生持久化及安装证据；模拟传输和交叉编译不满足此要求。

## Risks

草稿保存失败时不停止任何任务。如果后续检查点在任务停止后失败，Host 保持可见的暂停状态并拒绝安装；中断的工作不自动重启。未知生产者、缺少原生持久化能力或发布凭据仍是明确阻断。受支持的本地进程树观察器无法证明任意脱离其所有权的守护进程已经退出。
