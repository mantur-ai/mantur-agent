# Agent Note: 让失败的服务端工程保存保持可重试

Status: implemented

[English](2026-10-24-mantur-cut-save-fallback.md) | 中文

## 问题

浏览器缓存写入无法确认服务端或桌面工程已保存。将暂时不可用的共享存储当作独立本地存储，会让重试在未更新权威工程时报告成功，进而允许编辑器清除未保存状态并返回工程列表。注入传输故障时的这一失败行为不能证明历史用户事故的原因。

## 决策

维护的 [Cut 退出补丁](../../../../packages/client/ui-mantur-editing/adapters/mantur-cut-shutdown.patch) 根据已配置后端或可用的 HTTP／桌面传输选择工程持久化方式，不依赖远端缓存是否初始化。远端传输上的工程写入必须收到已接受的工程文档响应。初始化或写入失败不授权仅在本地保存工程；后续尝试仍重试同一权威存储。保存错误会保留未保存编辑，并阻止离开前的保存操作。

没有远端传输的独立存储及显式配置的本地后端保留既有行为。本地恢复数据和待同步条目继续可用，但不构成服务端确认。所有权、版本和 epoch 检查继续生效。[保存基线决策](2026-10-24-mantur-cut-persisted-save-base.zh.md)与[离线检查点决策](2026-10-24-mantur-cut-offline-checkpoint.zh.md)继续分别约束已确认版本和草稿恢复。

[桌面源码配置](../../../../apps/desktop/mantur-cut/source.json) 固定维护补丁的摘要和结果树。本次变更位于编辑器适配器中，无需修改 Harness 核心。

## 考虑过的替代方案

**传输失败后继续返回本地保存成功。** 这保留了上游离线写入预期，却错误表示已绑定服务端工程的保存位置，并允许在权威文档未变时离开。

**禁用所有本地存储。** 独立本地工程不依赖服务端确认，远端操作失败后的恢复数据也仍有价值。

## 后果

绑定服务端的工程需要服务恢复可用后才能保存成功。重试保留已确认基线，不采用其他写入者的版本。浏览器缓存写入成功不能解除未保存状态或导航保护。

验证使用隔离的真实 HTTP 和文件存储，覆盖重复 503 与断连失败、服务恢复后持久保存与重开，以及所有权拒绝时不返回本地成功。本地模式兼容性及既有 dirty-reconnect 和离线回归仍为必需检查。录制会话和安装包 GUI 验收必须另行针对修复后的源码执行；这些源码检查不批准发布。
