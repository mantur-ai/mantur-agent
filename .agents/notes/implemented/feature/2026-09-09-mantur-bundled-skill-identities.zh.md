# Agent Note: 精确的 App 内置 Skill 身份

Status: implemented

[English](2026-09-09-mantur-bundled-skill-identities.md) | 中文

## 问题

首页预设必须在未安装 Skill、未登录广场时仍可使用。用户目录可能存在旧版同名 Skill，因此仅按名称解析无法确定 App 所选的指令。

## 决策

桌面分发固定 ZIP 及完整文件清单。资源准备校验压缩包哈希并限制解压；加载校验每个文件以及指令名称与版本。身份由规范名称、版本及排序文件清单的摘要组成。资源位于用户与项目 Skill 根目录之外，使用对应身份的独立目录。

首页插入 `mantur-bundled-skill` 引用。序列化器校验身份后输出 `/mantur-builtin:<name>@<version>#<digest>`。广场 Host 只在直接用户消息中识别该手势，通过现有带来源消息的 pre-step 机制追加已校验正文。`skill-invocation` 来源记录版本与摘要。资源缺失、内容变化或不允许用户调用时拒绝加载，不进行替代。

普通 `/name`、已安装 Skill 和模型选择的 Skill 保留[Skill 注册表解析](2026-07-05-skill-system.zh.md)。文件系统解析器接收已读取 Markdown，让内置包加载解析的正是通过校验的字节。首页选择不覆盖用户内容，也不提交草稿。在线发现仍由显式“更多技能”操作触发。

## 考虑过的替代方案

**让内置根目录全局优先。** 这会在首页预设之外覆盖用户与项目的主动定制。

**把内置包复制到用户目录。** 这会混淆 App 资源与用户所有内容，并要求启动写入或覆盖策略。

**本地资源缺失时使用在线目录。** 这会隐藏打包缺陷，悄悄改变所选版本或账号要求。

## 影响

[无密钥 headless 场景](../../../../snapshots/session/mantur-bundled-skill/snapshot.yml)通过随产品提供的 `dsh` profile 挂载生产注入钩子。记录的请求包含所选正文与内置来源，同时普通目录仍保留同名旧版用户 Skill。

App 更新可以提供新身份，而保存的引用保留所选版本。运行中的 App 不包含旧引用时明确失败；已记录的指令保持不变。资源摘要检测相对内置清单的字节变化，不代表独立认证的发布者签名。

定向测试覆盖四份已审计压缩包、文件篡改与缺失、链接、frontmatter 版本不一致、离线 Host 读取、同名用户副本、仅直接用户消息注入及来源记录。UI 测试保留在线安装取消与草稿转移覆盖，并增加离线选择。内容来源批准和再分发权利独立于技术包校验；没有受支持根入口的套件不会被转换成普通 Skill。
