# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

漫途Agent 面向希望减少重复操作的漫剧和 AI 视频创作者。他们在桌面客户端中查找可复用的创作能力和经过验证的案例，再把自己的人物、场景或素材交给 Agent 处理。

## Product Purpose

产品通过把技能和可复现配方直接接入对话，让用户从一个已验证的结果出发，减少手工搜索、复制参数和串联工具的工作。成功意味着用户能看懂一份配方会产生什么结果、需要替换什么内容，并把它交给 Agent 继续创作。

## Positioning

配方不是通用工作流模板，而是一份带有效果、用例、可替换输入和复现说明的优秀案例。它与对话直接衔接，使 Agent 能读取可持久、可追溯的配方上下文，而不是让用户自己拼接提示词。

## Operating Context

用户从漫途侧栏进入技能广场或配方广场。广场是 Electron 桌面客户端内的 Web 界面，与项目和对话共用同一应用布局。公开目录允许未登录访问；只有真实 ManturHub API 要求授权的操作才进入登录流程。

## Capabilities and Constraints

- 目录和详情必须来自真实 ManturHub 数据，不得用模拟或默认案例伪装加载成功。
- 页面需要呈现加载、空、失败和重试状态。
- 已安装技能可以直接进入新的默认命名会话，并把 `/<skill-slug>` 放进输入框供用户补充任务。
- 用户从配方进入创作时，系统会开始新对话，并保留模型可读的配方来源和内容。
- 客户端文案由类型化本地化字典统一管理。
- 现有侧栏、项目和对话行为保持不变，不为配方广场新建一套桌面运行时。

## Brand Commitments

产品名称是“漫途Agent”，并使用已确认的蓝色无限环标识。语言应让用户感到 Agent 在接手繁琐的做剧工作，但不直白喊口号。配方广场延续当前轻量、清晰的桌面应用语气。

## Evidence on Hand

仓库已有漫途导航、技能广场、ManturHub 远程目录和设备登录实现。用户提供的配方广场参考稿明确了列表与详情的内容层级。真实案例、封面、价格、复制次数和创作者数据必须由 ManturHub 提供，不得从参考稿中捏造。

## Product Principles

- 用真实结果帮助用户做决定。
- 把可替换内容与不可改的复现条件说清楚。
- 让从案例到 Agent 创作的路径短而可追溯。
- 只在后端明确需要时要求登录或支付。
- 失败时告诉用户真实状态，不用假数据掩盖问题。
