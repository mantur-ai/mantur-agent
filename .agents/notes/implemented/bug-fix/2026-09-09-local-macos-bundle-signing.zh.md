# Agent Note: 本地 macOS 候选归档前完成应用包签名

Status: implemented

[English](2026-09-09-local-macos-bundle-signing.md) | 中文

## 问题

关闭证书自动发现后，普通打包跳过了应用签名。Electron 可执行文件保留链接器提供的 ad-hoc 身份，但没有绑定 Info.plist，也没有封装应用资源。应用可以通过受控启动检查，却无法通过 `codesign --verify --deep --strict`。

## 决策

在既有发行命令之外提供明确的 Apple Silicon 本地打包命令。它使用 electron-builder 支持的 `identity=-` 和严格校验，关闭证书自动发现及公证，保留标准签名器和权限配置选择。签名发生在资源装配完成后、归档创建前。系统 DMG 构建器执行前还必须通过第二次严格签名校验。

本地候选使用独立构建副本，保留旧应用和归档。打包完成后不得修改已签名内容。本地验收检查应用签名及 DMG 中提取出的应用，并在交接测试前记录产物校验值。

## 考虑过的替代方案

**跳过签名，仅将结果描述为未公证。** 这会掩盖应用包完整性检查失败。

**重新签名已冻结应用，或关闭系统检查。** 重新签名会改变已验收产物的标识；绕过系统检查不能证明完整性。

## 影响

本地命令不会自动发现 Developer ID 身份、提交公证请求或发布产物，也不改变正式签名发行工作流。Ad-hoc 完整性不等于 Apple 信任、公证、Gatekeeper 认可或公开更新批准。打包运行时检查、真实浏览器授权及客户端行为仍需分别在最终候选上验证。
