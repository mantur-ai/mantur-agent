# Agent Note: 恢复失效 MCP HTTP 会话且不重放调用

Status: implemented

[English](2026-09-07-mcp-http-session-expiry.md) | 中文

## Problem

MCP SDK 通过带结构化 HTTP 404 的 `onerror` 报告不存在的 Streamable HTTP 会话，同时保留旧会话 id，不触发 `onclose`。现有监督器因此留下表面仍连接的客户端，后续调用持续发生相同错误。本次事故发生在通过终态编辑会话 id 读取已应用草稿之后，已保存剪辑仍然完整。

## Decision

MCP 客户端只识别已完成连接与工具发现、拥有 HTTP 会话 id 且仍为当前代的 SDK `StreamableHTTPError`，并要求错误码为 404。监督器立即将该代标记为不可用，通过已有同步队列撤下工具注册，关闭本地 Client，同时等待关闭操作完成及传输关闭信号。既有五秒关闭上限在无法确认关闭时停止恢复。完全关闭的代按既有有界重连策略，使用相同端点与凭据创建全新的 SDK Client 和传输。

代际检查阻止迟到工具列表替换当前注册、已取出的旧执行器继续发送请求，以及已失效代的迟到调用结果被报告为成功。并发失效信号只停用该代一次。释放会取消退避并等待已拥有的停用过程。启动端点错误、HTTP 401/403、普通 JSON-RPC 错误和工具错误不进入会话失效路径。Stdio 保留既有重连及工具注册行为。

这是[自动重连记录](../feature/2026-08-06-mcp-client-auto-reconnect.zh.md)中 HTTP 和工具保留决策的有限例外；原有尝试预算、稳定窗口与 stdio 替代方案仍适用。不需要修改 agent loop 或编辑器协议。即使禁用自动重连，HTTP 会话失效也会移除工具。重连成功只重新发现工具，不恢复服务端项目绑定或编辑草稿归属。失败的工具调用不会重放，本地关闭也不能确定远端修改是否已经提交。

## Alternatives considered

**初始化后重试失败工具。** 响应失败前，修改可能已经提交。重放导入、时间轴修改或审核可能造成重复，明确续做前必须先检查已保存状态。

**把所有传输错误视为失效。** 认证失败、普通工具错误和网络中断不能证明 MCP 会话不存在。这些错误保留原有处理路径，不引入错误文本匹配或服务商切换。

**增加剪辑专用重连接口或放宽 owner 校验。** 缺陷属于共享 HTTP 监督器。新接口无法修复其他 MCP 客户端；重新初始化后接受旧草稿 owner 则会绕过编辑器的归属与版本规则。

## Verification

真实 HTTP 测试覆盖不携带旧会话 id 的初始化、一次失败且不重放的线路调用、并发失败、关闭完成与超时、释放、禁用恢复、预算耗尽、普通错误、独立 Agent 作用域及服务名称。受控迟到响应验证工具列表与执行器的代际检查。既有 stdio 和原生 MCP 测试覆盖正常连接与崩溃恢复。

无需 Key 的 Web 录制会话通过真实 Loader 与 MCP 客户端执行失败调用、移除工具，以及重新初始化后的明确调用。服务端拥有的初始化屏障使不可用区间保持确定；比较完整持久化会话、工具错误和三个请求头。模型和远端 MCP 端点均为明确的测试替身。这证明集成与日志，不证明自然语言剪辑质量或活动剪辑工程恢复。

## Consequences

HTTP 会话失效会在恢复期间改变模型可见工具列表，牺牲提示前缀复用，以避免继续把不存在的会话展示为可用。已发出的远端修改仍可能结果不明。剪辑 Agent 必须绑定浏览器中的项目，在创建下一草稿前核对已保存素材和时间轴；重连本身从不表示剪辑或导出已完成。
