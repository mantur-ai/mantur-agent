# Agent Note: 关闭传输前等待所属 MCP 执行完成

Status: implemented

[English](2026-09-07-mcp-owned-shutdown.md) | 中文

## Problem

关闭 MCP 客户端可能在远端回复或本地图片附件保存之前中止已接收的工具调用。Cordis 只记录释放失败，因此等待 Fiber 释放不能证明连接、远端应用或持久写入已经完成。更新协调器需要一个失败始终可见的明确结果。

## Decision

[MCP 客户端](../../../../packages/mcp/mcp-client/README.zh.md#owned-shutdown) 拥有执行准入截止点和每个已接收执行器 Promise，包括附件物化。句柄将关闭准入与传输释放分开，并允许应用提供远端排空前置条件。关闭准入保留当前连接世代和调用方取消信号。真正的取消仍然属于失败；Host 协调器必须先冻结新轮次，并将中止已接收轮次推迟到排空完成之后。

重复关闭请求共享首次 Promise 及其失败。传输完成同时要求关闭操作和关闭通知；失败或过期连接世代保留的错误也会阻止成功结果。名称预留在连接清理成功之后释放。排空超时会保留尚未完成的远端工作并拒绝关闭，不允许安装或重放修改。

此行为属于既有共享连接实现，因为剪辑插件无法观察执行器收到回复后的附件写入，也无法观察监督器已停用的传输。受影响的上游文件为 MCP 的 `index.ts`、`connection.ts` 和 `tools.ts`；无需修改 agent-loop、Cordis 释放语义或 MCP 线路协议。剪辑应用仍负责自身任务、工程保存与子进程关闭。

## Alternatives considered

**仅等待插件 Fiber。** 并行且只记录错误的释放操作可能先释放名称或关闭传输，再完成依赖工作。其汇总完成不是权威的成功结果。

**让已接收调用脱离取消，或重连后重试。** 这会掩盖用户取消，并可能重复执行首次结果不明的远端修改。

**把 HTTP 关闭当作远端刷盘。** 本地传输关闭无法证明工程持久化或付费工作完成。应用专属前置条件必须通过既有运行时建立这些事实。

## Consequences

清理结果不明时，关闭可能拒绝并保留资源预留。这有意阻止新的所有者或安装器把未知状态当作完成。恢复沿用既有连接策略；重连成功不会从所有者的关闭结果中擦除先前清理失败。

升级证据覆盖已接收调用的迟到回复及图片写入、新调用拒绝、取消与持久化错误、所有者排空失败及超时、重复关闭、连接世代停用、名称归属，以及关闭通知先于其 Promise 完成。无需 Key 的 Web 录制会话固定模型可见拒绝，并验证远端修改请求数为零。这些检查证明 MCP 归属，不证明完整编辑器或 Host 关闭。
