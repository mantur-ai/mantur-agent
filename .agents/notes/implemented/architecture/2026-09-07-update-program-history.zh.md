# Agent Note: 执行历史在更新关闭后继续保留

Status: implemented

[English](2026-09-07-update-program-history.md) | 中文

## Problem

worker 或动态插件注册表为空，并不证明任意程序后代已经停止。在更新协调器启动前移除服务，也会让仅检查实例的审计看不到该服务。

## Decision

worker 提供方记录每次尝试启动 worker。动态 runner 记录每次已接纳的激活，包括仅 Client 的激活。两个模块分别使用以 Host 根为键的单调 WeakSet 保留历史；即使所有提供方实例已经移除，导出的查询仍然可用。隔离和替换实例共享该历史。另一个 Host 根的历史相互独立。语法失败、提前取消的 worker 请求、定义和未回答的审批不会记录为执行。

动态 runner 同步关闭定义、激活、Client 源码和 handler 调用准入。它的关闭取消未回答的审批，等待已接纳的激活和 handler 调用，再等待正常插件回收。每次关闭请求都保留回收失败。worker 提供方保留既有的 worker、管道和已接纳绑定调用排空。两种操作都不证明任意后台工作或操作系统后代已经完成。

Mantur 协调器在等待生产方之前冻结两种执行服务。它在开始关闭前及每次回执前检查根历史和每个保留的服务，包括根销毁后的校验。缺少历史或已有执行都会阻止回执。在 Shell 完成策略未明确时，保留既有 codeRuntime 存在门禁和已发布 Host runner 模块排除规则。默认及自定义组合都不会仅因这些执行服务未使用而获得安装准入。模块 HMR 仍被排除。

## Evidence

真实 worker 测试区分解析或提前取消与 worker 执行。服务测试覆盖 stop、undefine、移除和隔离替换后的历史保留，并以独立根作对照。handler 和激活屏障证明关闭等待已接纳工作；handler 失败仍会结束，回收失败保持拒绝，并且拒绝新执行。消费者测试拒绝在协调器创建前已移除提供方的执行历史，并在回执后重新检查历史变化。记录式 CLI 场景配对验证受管理组合被接受和未使用 worker 组合被拒绝，并在各自 Host 退出后验证物理会话日志。

## Alternatives considered

**使用当前运行集合。** 它会丢失已完成或已移除的执行。**把受管理的停止成功视为后代完成。** worker 终止和插件回收无法确立该事实。**改变执行隔离。** 本变更保留当前 Shell 和 Node 能力；操作系统隔离不在范围内。

## Consequences

即使从未使用，worker 和已发布 Host runner 提供方仍会阻止自动安装。任何之前的 worker 或动态激活都要求在此自动路径以外的安装前人工处理未验证的后代。默认 profile 自动安装仍未验收。剪辑/MCP 继续被排除，直到其所有者在 AgentLoop quiesce 取消信号前排空已接纳执行和素材写入。用户取消或远端完成状态不明必须阻止保存回执；仅有 origin 路由独立不能证明完成。
