# Agent Note: 为 macOS 原生暂存测试分配预算

Status: implemented

[English](2026-10-24-macos-native-fixture-budget.md) | 中文

## 问题

[原生暂存测试](../../../../scripts/mantur-cut-resources.spec.ts) 等待编译、Mach-O 检查与重定位、临时签名与验证，以及三个已签名可执行程序退出。一次计时运行包含 33 个成功命令，没有 signal 或 spawn 错误；总耗时为 6.99 秒，其中仅三个可执行程序启动就耗时 6.19 秒。默认 5 秒测试期限在基线运行的 8.32 秒和独立评审运行的 7.12 秒处也触发失败。另一次报告的默认预算运行在 3.8 秒内通过，说明耗时存在变化，并不说明期限始终足够。macOS 启动延迟的具体原因仍未证实。

## 决定

仅 macOS 原生用例采用 30 秒测试预算下限，与其已有的单命令限额一致。这是由已测量完成工作支持的有界策略选择，不是测得的最坏情况上限。文件共享的临时目录清理在 macOS 上采用相同下限，让清理在宿主资源竞争时能够等待删除完成；其他平台保留配置的钩子预算。两项下限都通过已有的 coverage 预算解析器，保留 `DSH_COVERAGE_TEST_TIMEOUT_MS` 提供的更高预算。单独的 CLI 超时不能覆盖这些显式局部值。Windows coverage 流水线的 90 秒设置不是 macOS 已有的限额；该原生用例在 Windows 上跳过。

## 考虑过的替代方案

**保留五秒。** 仅已测量的成功子进程执行就超过该期限；更快的重跑不能推翻这项证据。

**模拟、重试、跳过或扩大全局预算。** 这些方案要么去掉真实原生加载证据，要么改变无关测试。断言、平台跳过条件、命令期限和全局配置保持不变。

## 影响

本决定调整测试对调度耗时的容忍度，不修复产品重定位、签名或 macOS 启动延迟，并保留[暂存决定](../bug-fix/2026-09-09-mantur-native-resource-staging.zh.md)。同步子进程等待保留其已有局限：外层 Vitest 期限不能硬中断阻塞的命令，30 秒也不保证所有命令都能耗尽各自上限。清理没有单独测得的 30 秒需求；其匹配下限遵循仓库的测试与钩子配对预算规则。较慢的失败可能需要更长时间才能报告。

聚焦验证在默认运行器设置下，以及 coverage 环境变量提供的 90 秒测试和钩子预算下均通过。原生测试保留真实编译、签名、可执行文件输出与递归重定位断言；这些证据不覆盖应用打包或发布验收。
