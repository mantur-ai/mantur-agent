# Native account cancellation

English | [中文](README.zh.md)

First-attempt provisioning seals its request before contacting the issuer. Skip cancels the caller's wait for that first write without waiting for the OS cipher to return. The store retains the accepted OS operation for shutdown and checks cancellation before encryption and before committing its result. A late result cannot create an account record or initiate a login request.

This does not interrupt an operating-system authorization dialog or detach shutdown from accepted storage work. Cleanup of existing attempts and grants still waits for exact cancellation or revocation processing. See the [decision](../../../../.agents/notes/implemented/feature/2026-09-09-cancel-pending-account-encryption.md).
