# Agent Note：等待重叠检查点写入完成

Status: implemented

[English](2026-09-07-projection-checkpoint-test-join.md) | 中文

## 问题

投影缓存顺序测试释放第一次写入的持久化屏障后，以独立的一秒期限轮询存储行。Windows CI 读到了创建时的检查点，而断言期望后续回合检查点。单凭这一现象无法区分写入延迟和顺序缺陷。

## 决定

测试观察两次真实的 `SessionProjectionCache.write()` 调用。它阻塞第一次持久化屏障，验证第二次屏障尚未启动，再释放第一次屏障，等待两次调用返回的 Promise 后读取实际存储行。清理时释放受控屏障、等待已准入的写入并恢复两个 spy。产品持久化行为和超时设置保持不变。

## 验证

在第二次持久化屏障中临时加入 1.2 秒延迟，原测试失败，修订后的测试通过。移除每个会话的写入链后，修订后的测试失败。普通投影缓存测试验证不含两种注入的最终 fixture。这些对照证明断言存在独立期限竞争，并保留了顺序检查；它们不能确定原 CI 延迟的原因。

## 考虑过的替代方案

延长轮询会增加另一个任意存储期限。在断言中调用 `write()` 会创建额外检查点，可能掩盖强制写入缺失。两者都没有验证创建和回合结束触发的两次操作是否完成。

## 后果

运行器现有测试预算仍约束停滞的写入。写入缺失、写入拒绝、持久化屏障并发以及最终存储行错误都会使测试失败。
