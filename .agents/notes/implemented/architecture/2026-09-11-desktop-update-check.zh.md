# Agent Note: 常驻桌面更新检查

Status: implemented

[English](2026-09-11-desktop-update-check.md) | 中文

## Problem

常驻更新卡片在没有新版时仍占用对话侧栏。手动检查需要在产品设置内提供容易找到的入口。

## Decision

通用设置负责已安装版本、手动检查与重试。侧栏在两种宽度下仅展示可下载、下载中和待安装状态；空闲、检查中、无新版及错误状态不显示在侧栏。两处注册共用一个原生订阅和控制器。只有原生版本检查成功才显示暂无可用更新；[发行版本决策](../bug-fix/2026-09-12-github-update-version-check.zh.md)定义旧发行的处理。明确下载及安装确认保持不变。

打包工作流随安装包保留生成的更新清单和 blockmap。CI 附件可用与向配置的更新源发布签名版本是独立事项。

## Alternatives considered

只在原生菜单提供检查可以节省侧栏空间，但常用产品导航中缺少发现新版的操作。将更新源不可用显示为已是最新版会掩盖发布失败。

## Consequences

后台检查在发现新版前不占用侧栏空间。浏览器构建仍不提供安装器。已安装客户端必须通过实际安装才能获得此界面；源码修改和 CI 附件本身不能修复空的正式更新源。

## Verification

组件回归覆盖设置内的手动检查，以及两种侧栏宽度下空闲、检查中、无新版和失败状态的隐藏。真实漫途浏览器组合记录这些状态，并通过隔离原生桥验证检查、下载和安装操作。原生正式版本发现及安装需要针对已发布产物另行验证。
