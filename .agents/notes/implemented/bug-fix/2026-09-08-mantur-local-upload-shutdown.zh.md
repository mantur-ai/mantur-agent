# Agent Note: 关闭编辑器前等待本地上传完成

Status: implemented

[English](2026-09-08-mantur-local-upload-shutdown.md) | 中文

## 问题

上传路由丢弃异步结果，编辑器退出无法确认已接受的上传完成。在不支持硬链接的文件系统上，既有独占复制发布路径等待文件句柄关闭，但已经完成写入的流仍持有引用。关闭句柄可能一直等待，且错误被吞掉。

## 决策

路由返回原始上传 promise。退出管理仅接受隔离运行配置下精确指向 `/upload` 的 POST 或 PUT 请求。该既有配置排除 R2 镜像和历史上传同步。默认配置、DELETE 和上传插件其他路由仍未确认。

既有独占复制路径保留写入流，在复制后销毁流并等待实际 `close` 事件。销毁流释放文件句柄引用；关闭错误沿上传结果传播，并保留在退出失败记录中。已接受的请求体和存储工作在浏览器保存前完成。准入截止后的请求返回 503。

## 考虑过的替代方案

**允许整个上传插件。** 其他路由及默认配置的后台工作没有这份完成证据。

**忽略文件关闭错误或增加退出超时回退。** 两者都不能证明已接受的文件操作完成。既有复制路径必须释放流引用并保留错误。

## 影响

七个模块内 HTTP 回归使用新建的 0.2 秒 H.264 夹具：POST 后抽帧、PUT、请求体跨越退出准入截止、延迟复制关闭、关闭失败、去重和未支持的 DELETE。验证上传字节与哈希、源文件不变，以及成功后的临时文件删除。负向控制分别丢弃处理函数完成结果、吞掉关闭错误、错误允许 DELETE；均触发对应断言失败。既有上传路由及五个 HTTP 退出回归继续通过。

浏览器冻结和保存确认采用受控 broker 夹具。这些检查证明后端媒体及请求完成，不代表已安装客户端界面、AgentLoop 附件、文件系统属主权限保证或原始剧集剪辑。上传修改不增加依赖、云端操作或公开 MCP 工具。
