# Agent Note：等待计时器触发的持久化写入

Status: implemented

[English](2026-09-07-live-write-test-barrier.md) | 中文

## 问题

JSONL 批量写入测试推进批处理时钟后，用独立的一秒期限轮询存储。即使批处理计时器已经触发，只要写入尚未在该期限内完成，测试就会失败。CI 在这条断言中读到了空事件列表。

## 决定

共享 live-write fixture 观察真实存储方法，不替换其实现。测试断言批处理窗口前方法尚未启动、窗口到点后恰好启动一次，等待该次调用返回的 Promise，再读取存储事件。测试在清理时恢复观察器并关闭句柄和上下文。不修改产品行为或超时。

## 验证

在真实存储写入前临时加入受控延迟，原轮询断言失败，更新后的 fixture 通过。普通 JSONL 所有者测试验证最终 fixture。该延迟证明断言存在独立期限竞争，但不能确定原 CI 存储延迟的具体原因。

## 考虑过的替代方案

延长轮询超时会增加另一个任意存储期限。调用 flush 可能自行启动写入，掩盖批处理计时器失效。两者都无法证明本测试应验证的定时操作。

## 后果

测试运行器现有预算约束停滞的存储。计时器未触发、重复调用存储、写入拒绝或持久化事件错误仍会导致测试失败。
