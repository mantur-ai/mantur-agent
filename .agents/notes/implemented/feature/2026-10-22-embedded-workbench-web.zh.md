# Agent Note: 在对话旁显示本地技能网页

Status: implemented

[English](2026-10-22-embedded-workbench-web.md) | 中文

## 问题

全自动漫剧生产线技能通过本地网页服务提供工作台。用户需要在对话旁查看该页面。页面的框架限制阻止 iframe 嵌入，而外部浏览器会让工作台与对话分离。

## 决策

[剧本工作台外框](../../../../packages/client/ui-mantur-script/README.zh.md)提供支持手动输入 URL 的“网页”标签。`open_web_page` 工具通过既有会话工具流程记录本地页面请求；客户端响应成功的实时结果，不重放历史打开操作。工具请求展示页面，不启动技能服务，也不证明页面已加载。

[桌面载体](../../../../apps/desktop/README.zh.md)拥有隔离的 `WebContentsView`。接受的地址使用 HTTP、字面主机 `127.0.0.1` 和显式端口，并排除应用自身 origin。原生视图不加载 preload，不提供 Node 访问，启用沙箱、上下文隔离和独立内存浏览器会话。Main 只接受受信任应用主框架的 IPC，将导航限制在打开时的 origin 内，并拒绝权限请求、下载和弹窗。技能的 CSP 与框架限制保持完整。

视图占据既有右侧工作台区域。切换标签或隐藏面板会隐藏原生视图，不停止技能服务。普通浏览器部署明确提示缺少桌面能力。打开页面不涉及技能身份、已安装技能内容、账号存储或对话草稿。

此功能扩展[共享剧本工作台](2026-09-09-script-workbench.zh.md)。[剪辑运行时](2026-09-06-mantur-local-editing-workbench.zh.md)与[布局保留机制](../bug-fix/2026-09-07-hide-editing-workbench.zh.md)继续独立负责各自功能；网页视图不替换其运行时或草稿生命周期。无需修改 agent-loop。

## 考虑过的替代方案

**用 iframe 嵌入技能页面。** 页面拒绝框架嵌入。移除安全响应头会改变技能服务器策略，而原生浏览器视图不需要这样做。

**打开外部浏览器或独立应用窗口。** 两者都会将页面与对话分开，无法提供用户要求的右侧标签。

## 影响

桌面可在保留可见对话的同时显示本地生产工作台。原生隔离使加载的页面无法使用应用 preload 或浏览器会话。功能限于本地 HTTP 服务，不支持任意公共网站或普通浏览器部署。

成功工具结果表示展示请求，不表示生产完成或导航成功。界面单独报告页面打开失败。隐藏视图不等于停止服务；技能继续负责服务器与生产任务。

可选剪辑提供者缺失时，剪辑标签仍保持可见。选择后明确提示需要配置匹配的 Mantur Cut 运行资源，工作台不模拟编辑器。开发桌面仍需要显式配置已验证的资源路径，安装包则提供其内置资源。
