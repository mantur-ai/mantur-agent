# Agent Note: 让 Agent 打开所属剪辑工作台

Status: implemented

[English](2026-09-09-mantur-agent-editing-entry.md) | 中文

## 问题

剪辑插件只在 Client 调用 Remote 打开后注册原生工具。用户尚未打开面板时，Agent 无法发现启动剪辑的入口。

## 决策

剪辑插件启动时，通过既有工具注册机制提供 `open_editing_workbench`。工具不接受会话、项目或目录参数。调用方 Agent 选择与 Remote 打开相同的运行实例；并发及重复打开复用该实例。`defineTool` 作为普通运行时依赖，因为每次调用创建独立工具定义；工具服务仍通过 `ctx` 注入。成功结果表示运行时和原生 MCP 就绪。项目绑定、草稿创建、审核、应用状态检查及保存仍使用编辑器原有工具。

成功结果携带 `sessionId`、`editorUrl` 和 `directory`。原生渲染是单个 JSON 文本块；展示元数据增加固定的 `mantur-editing-workspace` 标识。Host 从经过校验的本机端口构造地址，不含凭据或查询参数。Bearer 保留在 Host 连接中。启动失败和取消返回普通工具错误；取消不会销毁已经取得的会话运行实例。

Client 通过私有对话事件投影管理可见性。常驻边缘按钮挂载时开始观察。只有观察到现场打开调用从进行中变为成功，才能触发首次自动展开。原生调用读取结果元数据；PTC 调度读取指定入口工具及其单个 JSON 结果块。历史回放和切换会话不触发展开。用户主动收起后，该会话后续调用及轮次持续抑制自动展开。用户仍可手动展开或收起面板；手动操作不恢复自动展开。隐藏但仍挂载的页面保留相同工具和运行实例。模式选择不改变可见性。不引入通用工作台框架、替代剪辑通道或用户 MCP 配置步骤。

## 考虑过的替代方案

**仅在手动打开面板后注册原生剪辑工具。** Agent 仍无法自行启动用户要求的工作流。

**每次剪辑调用或匹配助手文案就展开。** 这会覆盖用户收起意图，或将未验证文案视为实际动作。既有持久工具事件能够标识实际调用及结果。

## 影响

Host 回归覆盖打开前发现入口、工具及 Remote 重复打开共用实例、不同 Agent 作用域、启动错误、无所属会话调用及取消。脚本驱动的 AgentLoop 打开运行时并调用既有 MCP 通道；持久工具结果核对入口元数据。无密钥的已发布配置快照固定打开工具 schema 和原生剪辑工作流。

这些检查不证明真实模型选择了正确剪辑。内置编辑器检查使用明确的本地夹具操作；报告区分打开、草稿应用、保存工程读回、隐藏 iframe 执行及最终漫途 Client 交互。打开工具不授予覆盖、删除、付费生成、导出或发布权限；保留既有确认流程。
