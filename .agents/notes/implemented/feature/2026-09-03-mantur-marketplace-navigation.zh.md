# Agent Note: 漫途广场导航

Status: implemented

[English](2026-09-03-mantur-marketplace-navigation.md) | 中文

## Problem

漫途Agent 需要在项目浏览器上方提供只属于产品的技能广场与配方广场入口。官方 Web 客户端必须保留“工作区”术语和对话优先的启动状态，同时广场 MVP 需要独立的中央页面，不能把可穿透的浮层伪装成主页面。

## Decision

`ui-layout` 在根 entry store 中保存临时的品牌化 `MainPageId | undefined`，并声明根作用域单 occupant 的 `main.page` slot。页面激活时隐藏但不卸载对话表面，在不修改详情栏首选宽度的情况下把详情栏渲染为零宽，并向页面提供恢复当前对话的关闭操作。store 不做持久化，因此刷新后始终从对话开始。

`ui-sidebar` 在 `sidebar.workspaces` 之前声明 `sidebar.navigation`，并向 occupant 传递当前页面以及打开、关闭操作。新建会话前先关闭页面。工作区浏览器接收同一个返回操作，并在打开、新建或 fork Session 前调用它。插件卸载或替换导致活跃的漫途根页面 occupant 卸载时，它也会调用关闭操作，因此临时布局 store 不会保留已经失去 renderer 的页面标识。

`ui-workspace` 声明嵌套的 `sidebar.workspaces.heading` slot，并以现有本地化“工作区”文案作为 fallback。只由漫途组合加载的 `ui-mantur-navigation` 同时填充三个扩展点：语义上的“功能”导航分组、本地化“项目”标题，以及独立的技能与配方页面。可视导航遵循已确认布局，不额外显示“功能”标题；无障碍导航名称仍保留分组身份。官方 profile 不组合这个包。

技能页面挂载生成的 Remote，并由一个根作用域浏览器 controller 管理目录、详情、安装和设备登录状态。新的 Host `manturhub-marketplace` 包校验 ManturHub 线上响应封装，只投影浏览器安全的元数据。所有认证请求与文件系统操作都由 Host 持有。安装时只有第一跳下载携带认证，第二跳必须是明确且安全的重定向，压缩包源永远不会收到凭据。安装器限制下载大小，把 ZIP 条目流式写入私有暂存文件，并在每次写入前拒绝跨平台不安全路径、链接、特殊节点、无法精确表示的大小、过多条目，以及声明或实际解压体积超限。它会再次检查解压后的文件系统，校验根 `SKILL.md` 的 name 与 version，然后通过同一文件系统重命名提交。受跟踪的内容哈希阻止覆盖本地修改，未跟踪目标也会失败。更新前，旧 Skill 会移到可发现 Skill 根目录之外的唯一恢复目录。状态提交失败时安装器会恢复它；如果回滚失败，则保留并报告准确恢复路径。实时 Skill 文件系统 watcher 会发现已提交的重命名，无需重启桌面应用。

已安装技能在目录卡片与详情中都提供“使用技能”操作。该操作通过现有 controller 解析当前工作区，创建默认命名的会话，经该会话作用域的 input facade 把 `/<skill-slug>` 写入尚未发送的 composer 草稿，打开该会话，再关闭广场页面。它不会提交命令，因此用户可以先补充任务内容，再调用技能。缺少当前工作区或会话初始化失败时，界面停留在广场并显示明确的恢复提示。

配方页面通过现有 Host 广场 Remote 读取 ManturHub 的公开分页目录与详情接口。Host 校验全部字段，接受以 UTC `Z` 或显式数字时区偏移结尾的发布时间并拒绝无时区值，基于已配置 Hub 的响应来源解析相对媒体与非空来源路径，从浏览器结果中省略空来源元数据，并原样返回已发布的 `agent_payload`。浏览器负责搜索、分类选择、列表与详情状态以及页面展示。配方仍是经过验证的创作案例，不是可安装包或通用工作流模板。

根作用域 controller 在插件生命周期内保留已完成的技能目录和当前配方查询快照。进入页面时会复用匹配状态，包括配方筛选条件和页码；相同且尚未完成的配方请求也会合并。更改筛选或页码会请求新数据。“重新加载”调用强制加载操作，因此不会用旧数据隐藏已知失败。缓存仅存在于内存，刷新或重启客户端后仍会冷启动。

“交给 Agent 复刻”会在当前工作区中新建会话，通过作用域化 Conversation 服务提交一条普通用户消息，并在消息成功后打开该会话。本地化边界使用当前界面语言生成包含配方标题、slug 与 ManturHub 标识的追溯文案；仅当 ManturHub 发布来源 URL 时才追加该地址。store 随后原样附加权威 `agent_payload`。模型因此看到发布者提供的相同说明，转录也能审计交接且不会捏造缺失元数据。配方发现保持公开；由于这些接口不要求认证，界面不请求登录，也不会因为会话接受了消息就宣称算子执行已经开始。

## Alternatives considered

**在 `ui-sidebar` 中硬编码漫途术语和链接。** 这样会把部署文案泄漏到官方 shell，并让共享包承担所有产品专属目的地，因此改由产品包拥有 occupant。

**在 `shell.overlay` 中渲染广场页面。** 该 slot 是可穿透的浮动层，底下的对话仍可被访问。把它当作主导航会造成错误的无障碍与布局行为。

**持久化选中的广场路由。** 需求明确要求每次刷新默认回到当前对话。把选择保留在现有临时布局 store 中即可满足，不需要第二套路由 store。

**把广场目录持久化到磁盘。** 当前延迟发生在同一次客户端运行期间切换页面时。磁盘持久化会引入过期、数据结构迁移和陈旧数据处理，却没有对应的离线需求，因此 controller 只保留会话内存。

**缓存每一种配方查询。** 任意文本搜索会让 controller 内存持续增长，但没有对应需求。只保留当前查询即可消除重新进入页面时的请求，同时限制内存占用。

**在浏览器中下载并解压。** 这会让展示代码接触认证信息和文件系统变更。生成的 Remote 把两者都留在 Host，只返回明确成功或类型化失败。

**覆盖现有目录或增加强制选项。** 浏览器无法确认本地内容是否可丢弃。安装器自有哈希只允许更新未改动的受跟踪内容，其他情况一律显示冲突。

**把配方安装成本地包。** ManturHub 把配方发布为复刻说明可能变化的在线案例。把 payload 写入持久用户消息可以保留这次交接的准确内容，而 payload 本身会在需要时指示 Agent 获取最新结构化参数。

**把配方上下文放在转录之外。** 仅存在于浏览器的路由参数或隐藏内存字段会在刷新后丢失，并违反“模型可见即有日志”的规则。普通用户消息复用既有会话准入路径，同时对用户与模型可见。

## Consequences

共享客户端增加两个通用扩展点和一个临时页面选择器，漫途文案与页面结构仍隔离在产品包中。同一组合只能安装一个根页面 occupant。漫途 profile 已提供技能目录读取、安全安装与未发送草稿交接。在同一个 controller 生命周期内重新进入任一广场时，都不会重复请求匹配的目录，配方页还会恢复当前筛选和页码。只保留当前配方查询，刷新后仍会冷启动。配方也可以被发现并持久交接给 Agent；交接后的算子执行、报价确认和支付仍由 Agent 与 ManturHub 负责。强制覆盖、卸载和路由持久化仍未提供。
