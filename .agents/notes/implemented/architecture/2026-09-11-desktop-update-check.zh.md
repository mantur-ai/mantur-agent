# Agent Note: 常驻桌面更新检查

Status: implemented

[English](2026-09-11-desktop-update-check.md) | 中文

## Problem

在发现更新前隐藏侧栏入口，会让手动检查依赖原生应用菜单。后台检查失败也会移除用户重试所需的操作。

## Decision

每个启用更新的桌面快照都在设置上方显示已安装版本和检查操作，两种侧栏宽度均保留。只有原生版本检查成功才显示暂无可用更新；[发行版本决策](../bug-fix/2026-09-12-github-update-version-check.zh.md)定义旧发行的处理。失败时保留重试操作。这部分取代[原生更新入口决定](2026-09-06-desktop-update-entry.zh.md)中的空闲卡片隐藏规则；控制器所有权、明确下载及安装确认保持不变。

打包工作流随安装包保留生成的更新清单和 blockmap。CI 附件可用与向配置的更新源发布签名版本是独立事项。

## Alternatives considered

只在原生菜单提供检查可以节省侧栏空间，但常用产品导航中缺少发现新版的操作。将更新源不可用显示为已是最新版会掩盖发布失败。

## Consequences

没有新版时侧栏仍占用空间。浏览器构建仍不提供安装器。已安装客户端必须通过实际安装才能获得此界面；源码修改和 CI 附件本身不能修复空的正式更新源。

## Verification

组件回归覆盖两种侧栏宽度下空闲、已是最新版和失败状态的手动检查。真实漫途浏览器组合记录这些状态，并通过隔离原生桥验证检查、下载和安装操作。原生正式版本发现及安装需要针对已发布产物另行验证。
