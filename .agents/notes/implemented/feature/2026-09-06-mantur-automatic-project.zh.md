# Agent Note: 漫途首次发送项目与持久未关联草稿

Status: implemented

[English](2026-09-06-mantur-automatic-project.md) | 中文

## Problem

创作者需要在选目录前开始编写。进入页面就创建项目会留下空项目，首次发送中断后的重试可能重复创建项目，或丢失已选图片和带中文标题的技能。桌面重启后使用不同端口，浏览器 origin 存储无法标识同一草稿。

## Decision

漫途使用明确选择 Workspace 的策略和常驻未关联编辑器。输入、切换创作模式、选择推荐和读取保存位置均不创建 Host 实体。首次发送通过[原生草稿检查点](../architecture/2026-09-06-desktop-draft-checkpoints.zh.md)持久预留 UUID，再由 [mantur-projects](../../../../packages/workspace/mantur-projects/README.zh.md) 准备目录，最后通过普通 controller 创建确定的 Session。[共享 Workspace 选择器](../simplification/2026-07-31-one-route-to-add-a-workspace.zh.md)仍负责用户明确选择路径；标准 Web 组合保留当前或最近项目选择。

桌面提供操作系统文档目录下的 `漫途项目` 子目录。所选根目录持久保存、发送前可见，并且只影响尚未预留的创建。独占创建绝不接纳已有内容。所有权回执不明确或目录被外部删除时显示错误；选择已有目录是独立的用户操作。

对话所有者等待两个编辑器的原生恢复，在发布转移前立即核验发起准备和当前选择，并提交同时包含已填充目标与已清空来源的单个检查点。完整 Lexical 文档保留中文名称、引用标识、occurrence 顺序和已选图片字节。选择其他对话会取消准备，回到首页不能恢复旧准备。发布前取消保留来源。写入期间取消或导航可能留下已持久转移的目标；此时禁止自动打开和发送，并提示未发送草稿的所在位置。清空来源不等于提示词已送达。

转移确认后，既有 Session input 执行普通提交。准备锁与存储锁分别拥有，释放其中一个不能解开仍由另一个持有的编辑器。[创作引导](2026-09-06-mantur-creation-guide.zh.md)直接插入常驻编辑器，不虚构临时 Session；模式切换仍不改变 Agent 身份或权限。项目目录与[会话日志存储目录](../architecture/2026-07-24-project-session-directories.zh.md)保持独立。

## Alternatives considered

**进入页面时创建项目。** 访问或关闭首页就会在未提交任务的情况下写入目录。

**单独保存浏览器创建标识。** 它可能与原生草稿分离，并随 loopback origin 消失。重试标识由持久草稿拥有。

**复制斜杠文本或分别保存两个归属。** 文本会丢失带标题引用，分开写入可能丢失或重复草稿。单个检查点先记录两个归属，再移动内存内容。

**回滚所有已取消操作。** 响应丢失不能证明 Host 未提交。复用记录标识并保留未发送目标，可以避免删除用户数据或假称已撤回完成的写入。

## Consequences

首次发送要求原生草稿持久化正常。存储错误、不支持的 Windows 发布和缺失桌面传输均明确失败，不用浏览器存储替代。部分创建的目录可能需要手动选择。普通 Session 接收与失败恢复继续拥有发送流程；本功能不承诺提示词接收后崩溃仍能实现恰好一次投递。

## Verification

Host 测试覆盖并发重试、重载、根目录变更、已有内容以及删除或替换目录。Client barrier 覆盖标识持久化、两种解锁顺序、发布前取消、保存回执丢失，以及转移期间导航或取消。真实漫途 Loader 浏览器场景丢失项目创建成功响应，刷新恢复完整技能与图片草稿，再双击重试，核验仅一个项目、一个 Session、一个提示词请求和一条持久用户消息。原生安装、Windows 持久性、真实凭据和付费生成不在这些证据范围内。
