# Agent Note: 原生目录选择器关闭等待子进程结束

Status: implemented

[English](2026-09-07-native-picker-shutdown-join.md) | 中文

## 问题

调用方的请求已取消，并不证明其操作系统选择器已退出。Node 的 `execFile` 可能在子进程 `close` 前调用中止回调；Windows worker 也可能在进程和流关闭前报告结果。仅取消连接还会遗漏浏览器连接建立前已受理的请求；在任一时点释放 Host 都可能留下运行中的选择器。

## 决策

[原生后端](../../../../packages/host/directory-picker-native/README.zh.md)持有已受理请求，直到进程关闭且输出读取完成。其稳定原生能力提供 `stopForShutdown()`，同步冻结受理、中止本实例的请求并等待它们结束；冻结前捕获的能力对象也不能再受理工作。插件释放使用同一次停止操作，重复调用保留其完成结果或清理失败。

[命令运行器](../../../../packages/util/native-command/README.zh.md)持有子进程，只在 `close` 后结束调用，同时保留原始错误字段。Windows 驱动保留已报告的结果，直到子进程关闭，并等待未完成的 `WM_CLOSE` 调用。既有重试和终止策略不变；拒绝终止或终止失败以 `NativeCommandCleanupError` 保留。普通选择器错误和用户取消不会否定已完成的清理；子进程若始终不关闭，停止操作就保持待定，请求失败不能替代进程退出证据。

这项修改为[能力接缝](../architecture/2026-07-28-directory-picker-capability-seam.zh.md)补充原生生命周期所有权，不改变其交互拆分、[自适应组合](../feature/2026-07-29-directory-picker-adaptive-default.zh.md)或 [Windows 机制](../feature/2026-08-02-win32-in-process-folder-dialog.zh.md)。这些决策保留各自独立的理由；停止操作仅供 Host 使用，不是 Remote 动词或浏览能力。

## 考虑过的替代方案

**只依赖连接中止。** 它遗漏启动阶段的请求，无法冻结已捕获的能力对象，也无法等待调用方已取消的子进程。

**把中止回调或 worker 结果视为完成。** 两者都可能早于进程和流关闭；取消进程引用或丢弃子进程记录会掩盖尚未完成的清理。

**只修改 POSIX 运行器。** Windows 驱动同样存在结果早于关闭的时序；公共原生停止承诺必须在两类驱动上具有相同含义。

## 影响

停止一个提供方不会停止另一个 Host 的选择器。调用方保留正常选择、取消和启动错误结果，但这些结果等待所持有的进程关闭；共享的路径打开消费方也等待其启动器进程，而不等待启动器打开的外部应用。关闭协调器必须先取消原生选择，再等待选择器 RPC 排空；本包不实现协调器，也不证明无关操作系统子进程已退出。

服务和真实 Loader 测试固定受理冻结、释放等待、调用方取消、实例隔离及清理失败保留。一个忽略 SIGTERM 的真实 POSIX 子进程固定中止回调与 `close` 之间的间隔；恢复提前结束行为会让该测试失败。受控 Windows 驱动测试固定结果、退出和关闭的顺序、待完成关闭窗口调用及终止失败；真实 Windows 对话框验收仍是独立平台检查，受控驱动覆盖不能替代它。
