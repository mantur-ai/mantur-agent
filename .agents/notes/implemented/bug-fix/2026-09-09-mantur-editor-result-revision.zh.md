# Agent Note: 完成工具调用前同步编辑器版本

Status: implemented

[English](2026-09-09-mantur-editor-result-revision.md) | 中文

## 问题

编辑器结果路由先完成 MCP 调用，再等待项目版本同步。后续调用可能以旧版本提交下一次编辑，在首次修改已保存后收到会话过期错误。该路由还会丢弃版本同步错误。

## 决策

第三层[编辑器源码补丁](../../../../packages/client/ui-mantur-editing/adapters/mantur-cut-shutdown.patch)通过 broker 完成浏览器结果。Broker 校验注册凭据和已派发调用，仅允许一个完成操作，同步权威项目版本后才完成 MCP 结果。无持久化所有权的注册仅豁免当前完成调用的版本变更取消；其他过期调用仍然失败。

Broker 在异步同步后重新检查待完成调用、注册信息和截止时间。注册表不会更新或注销替代连接。取消、过期和重复结果不能恢复已结束调用。同步错误使待完成调用和 HTTP 结果明确失败，不返回成功；保留的失败仍会阻止关闭确认。不引入重连、修改重试或过期检查豁免。

[桌面端源码配置](../../../../apps/desktop/mantur-cut/source.json)锁定更新后的第三层补丁和结果树。上游版本及前两层补丁保持不变。新资源按这些标识构建，不编辑既有冻结资源或正在运行的应用。

## 考虑过的替代方案

**收到成功后等待，或过期时重连。** 两者都不能让已返回的结果变得可信，重复编辑还可能造成重复修改。

**仅交换路由中的语句。** 这不能保证完成操作的唯一性，并可能在无持久化所有权的注册变更版本时取消正在完成的调用。

## 影响

编辑器的 `verify:mcp` 命令在既有 MCP 检查前执行确定性的路由和 broker 回归。回归阻塞真实项目存储队列，证明同步完成前 MCP 和 HTTP 均不返回成功，并覆盖后续调用绑定、无效凭据、重复结果、取消、过期、注册替换及真实存储故障。源码检查不代表打包 App 验收通过，也不代表真实模型的剪辑质量；隔离浏览器编辑和最终客户端验收仍需分别完成。
