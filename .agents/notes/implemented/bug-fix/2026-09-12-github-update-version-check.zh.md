# Agent Note：读取更新文件前比较发行版本

Status: implemented

[English](2026-09-12-github-update-version-check.md) | 中文

## Problem

先读取清单会让已安装的 0.1.7 因空的旧版 0.1.3 发行而失败。

## Decision

固定的 GitHub provider 在读取清单前比较已选语义版本标签。禁止降级时，相同或更旧的标签产生 `ERR_UPDATER_NO_NEWER_RELEASE`；原生控制器仅在检查期间接收该结果。不生成虚构清单，也不替换下载文件。更高发行仍必须提供真实清单和经过校验的安装文件。

更新失败把原始诊断保留在应用日志中，向用户展示简短本地化反馈。更高发行缺少清单表示不可用，不表示已是最新版。此决策细化[常驻更新检查决策](../architecture/2026-09-11-desktop-update-check.zh.md)的文案，不改变下载或安装确认。

macOS 签名流程明确选择 `arm64`，或默认选择 `both`。每个选中架构都必须通过签名、公证和打包后启动检查。选择 Apple Silicon 不会声称支持 Intel。正式发布仍受精确发行审核和不可变发行要求约束。

每个架构按明确的附件名称下载到各自目录，汇总路径不依赖通配符匹配的附件数量。

## Alternatives considered

把所有清单 404 视为已是最新版会掩盖不完整的更高发行。补丁使用 provider 现有版本选择，不重复发现发行。修改已安装的签名应用会破坏签名。

## Consequences

升级 electron-updater 时，必须同时调整 provider 补丁与控制器的结果处理。客户端检测修复不会发布更新文件；正式发布仍需要完整附件和配置好的审核。

## Verification

实际安装的 provider 测试覆盖更旧、相同、更高、不完整、预发布和明确降级。控制器测试覆盖事件与 Promise 交付，并区分原始日志和用户反馈。原生菜单及真实浏览器快照记录暂无更新文案。正式仓库检查验证 0.1.7 不再请求空发行 0.1.3 的清单。正式下载与重启升级仍需独立验收。
