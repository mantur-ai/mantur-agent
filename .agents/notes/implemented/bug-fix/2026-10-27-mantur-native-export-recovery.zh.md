# Agent Note: 将原生导出授权保留在选择文件的文档中

Status: implemented

[English](2026-10-27-mantur-native-export-recovery.md) | 中文

## 问题

Mantur 原生保存选择返回 JavaScript 文件适配器，其方法通过父窗口转发写入。IndexedDB 无法克隆这些函数，因此包含该适配器的服务端导出任务在渲染开始前就因持久化失败而中止。

## 决策

Mantur 适配器通过 WeakSet 登记自身的临时句柄。导出恢复存储持久化 handle 为 null 的文件描述，并按渲染 ID 将活动目标保留在选择文件的当前文档中。数据库事务提交后，内存目标才会更新；成功删除记录时也会清除内存目标。新文档恢复不带授权的描述，并使用现有的显式目标选择流程。真正的浏览器 FileSystemHandle 对象保留既有 IndexedDB 存储行为。

[嵌入式导出决策](2026-10-26-mantur-cut-embedded-export.zh.md) 继续定义原生选择、桥接和清理。该行为属于编辑器退出补丁，不改变 Harness 核心接口。源码清单绑定补丁摘要和编辑器结果树。编辑包的 [README](../../../../packages/client/ui-mantur-editing/README.zh.md) 定义使用方行为。

## 考虑过的替代方案

**吞掉克隆错误。** 这会让渲染在缺少必要持久化恢复记录时继续，也会掩盖其他存储故障。

**持久化原生授权。** 选择文件的编辑器文档关闭后，存储的授权不得允许继续写入。从持久化授权数据重建适配器会绕过显式重新选择。

**增加另一种目标传输。** 现有文件写入器和恢复描述已能表达当前文档使用及重新授权行为。第二条写入传输会重复这些路径。

## 后果

原生目标可用于当前文档内的阶段更新和重试。重新加载后的恢复需要用户重新选择目标。真正的浏览器句柄仍可恢复。写入或删除失败时，保留此前成功提交的内存目标。

编辑器命令 `verify:mantur-export-recovery` 使用 `CC_EXPORT_RECOVERY_BROWSER` 指定的已安装浏览器验证真实 Chromium IndexedDB，不下载浏览器。它覆盖未处理句柄的克隆失败、生产恢复存储的阶段推进、重新绑定、失败事务、删除、新文档重新选择及真正的 FileSystemFileHandle。原生选择窗口及桥接响应使用测试夹具，因此该检查不能替代签名应用的 GUI 验收。
