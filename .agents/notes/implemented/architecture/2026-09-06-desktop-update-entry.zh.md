# Agent Note: 原生更新入口与明确下载

Status: implemented

[English](2026-09-06-desktop-update-entry.md) | 中文

## Problem

后台发现更新时会打开下载对话框，再次操作可用更新则依赖原生应用菜单。renderer 没有进度入口；安装准备失败时，即使已校验的下载仍然存在，也会丢失就绪状态。

## Decision

桌面 updater 安静地发布可用状态，仅在明确操作后开始下载。受限于主 frame 的 preload 暴露带版本的快照和三个固定控制器操作。漫途导航插件拥有订阅，并在两种侧栏宽度下于设置上方渲染入口。旧快照回执无法覆盖新事件，dispose 会阻止迟到的 renderer 更新。

原生控制器拥有菜单和侧栏共用的单一安装确认。选择稍后会保留就绪入口，不重复弹窗。准备失败会保留已校验下载并显示错误，不声称安装已发生。现有最终 Host 检查点阻断仍阻止实际安装，不停止任何任务。

## Alternatives considered

单独的 renderer updater 会重复下载和确认职责。自动下载会移除明确同意。永久空闲卡片会在没有可用操作时占据空间。按时间猜测百分比会误报进度。

## Consequences

普通浏览器页面没有更新能力或模拟安装器。原生下载显示实际已传输字节，总大小或百分比未知时显示不定进度。现有 feed、发布通道选择、签名及架构对应产物仍是必要条件。该 UI 变更不提供 Windows 持久发布或可靠的 Host 关闭检查点。

## Verification

控制器测试覆盖明确下载、重复操作、未知总量、校验失败、稍后及准备失败。IPC 测试拒绝其他窗口和 frame；renderer 测试覆盖过期快照、dispose、收起操作及本地化进度。隔离浏览器 fixture 驱动真实漫途侧栏，不访问发布 feed 或调用安装器。原生包安装仍未测试。
