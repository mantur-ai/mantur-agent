# Agent Note: 遥测不属于更新保存回执

Status: implemented

[English](2026-09-07-update-telemetry-scope.md) | 中文

## Problem

模块名称检查会在权威数据保存前拒绝默认遥测后端，但遥测送达并不是用户数据持久化保证。

## Decision

Mantur 更新策略接受随附的 OpenTelemetry 后端，不把采集端送达作为保存前提。JSONL 会话记录仍是权威数据。遥测将这些记录复制到外部采集端，不改写源日志；其队列与送达结果不能证明用户工作是否已保存。

Host 保存协调器在发出回执前关闭并校验权威 writer。普通应用树释放仍执行现有遥测协调器和后端关闭。后端按配置期限限制 SDK 等待；关闭拒绝时，协调器记录告警。本变更不引入遥测回执、重试、取消路径、配置覆盖或提供方替换。Main 仍要求所属 Host 退出且诊断日志关闭；本变更不允许将任意挂起进程视为保存成功。

## Evidence

更新集成通过 Loader 挂载真实遥测后端，将会话事件入队，并在上传发生前验证持久 writer 偏移。私有采集端以 HTTP 503 拒绝上传；普通释放仍会访问它，重新校验 writer 的结果保持有效。现有遥测测试覆盖 SDK 关闭阻塞时的期限和关闭告警保留。录制的 CLI 关闭场景包含 disabled 模式的遥测模块并保留原始会话日志；这在不访问外部采集端的情况下验证模块接受策略。

## Alternatives considered

**要求采集端送达。** 即使本地工作已保存，网络故障也会阻止安装。**跳过遥测释放。** 这会放弃既有限时关闭及告警。

## Consequences

本例外只涵盖随附的遥测后端。动态 Host 代码、未管理 OS 后代，以及会写用户工程的剪辑/MCP 操作仍需各自的资源完成证据。权威设置、工程记录、用户反馈和会话写入错误仍会使安装失败。
