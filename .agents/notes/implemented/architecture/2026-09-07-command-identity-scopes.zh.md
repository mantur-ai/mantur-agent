# Agent Note: 命令身份与完整进程清理

Status: implemented

[English](2026-09-07-command-identity-scopes.md) | 中文

## 问题

桌面托管命令权限必须异步准备，不能发布尚不存在的进程。直接子进程可能退出，但后代仍使用其权限。在直接子进程退出时释放描述文件，或将发出 abort 当成完成清理，会使活动工作脱离账号退出和关闭流程的所有权。

## 决策

[command-scopes](../../../../packages/shell/command-scopes/README.zh.md)在身份准备前记录接纳，拥有完整分配与清理期间。subprocess 原语仍同步创建普通进程。shell 后台启动异步返回，job 钩子则同步拥有这个待定启动及其取消。不发布占位 PID 或进程句柄。

subprocess 提供方证明完整进程树或终端退出后，身份提供方才释放权限。进程分别暴露直接子进程完成与完整清理。后代比直接子进程存活更久时，取消仍保持连接。清理失败持续保留，并使关闭操作拒绝。Main 将 close-scope 回执视为消费方已完成清理，而不是新的取消请求。

关闭先同步冻结接纳，再等待已接纳的工作。迟到的身份租约和终端分配先完成清理，已取消的启动才返回拒绝。持久终端跨多次发送保留同一个身份租约，直到会话清理。协议子进程保留其协议所有者的生命周期。

## 考虑过的替代方案

**将所有 subprocess 创建改为异步。** 协议消费方不需要命令身份。更改原语会将异步分配扩散到无关的 LSP 与子 agent 传输。

**身份准备期间发布占位句柄。** 伪造的 PID 或完成回执不能证明真实操作系统进程归属，也可能使取消与迟到分配发生竞态。

**直接子进程退出时释放权限。** 后代可能仍然存活。命令必须等待提供方拥有的完整进程树，再释放身份。

## 后果

shell 消费方等待启动和完整清理，job 钩子覆盖待定准备。已取消的准备只有在执行器完成清理并返回消费方原有的取消原因时，才报告 killed 任务。其他准备失败与所有清理失败都报告 failed 任务，同时 commandScopes 独立保留清理失败以阻断关闭。身份取消参与首次原因的超时分类，即使清理持续到更晚的 deadline 触发也不改变首次原因。必需身份模式在没有提供方注册时拒绝接纳，绝不切换到独立凭据。

所有权测试覆盖迟到租约、迟到终端、进程树检查失败、释放失败和真实 POSIX 后代。Main 到 Loader 的集成通过本机账号端点验证真实 Bash、固定 CLI 和持久终端。原生表单、打包 CLI 交付、生产端点及操作系统凭据验收是独立要求。
